# Paper-Style Skill Forward Test

## Current Candidate

[v6 tilebench-analysis](skills/v6/tilebench-analysis/SKILL.md) targets the paper's
operator-level explanation: benchmark gap, selected implementation/configuration,
matching NCU consequences, selective SASS/PTX, and a named mechanism with limits.
Compiler source and exact pass attribution are optional. Lower utilization alone
is explicitly not a mechanism. Original ratio/numeric/action/static-vs-dynamic
invariants remain. This is an evolved repo-local skill, not a newly discovered
third-party skill or a home-installed replacement for ncu-report-skill.

Two fresh Luna/high/no-history runs used existing matmul FP16 M=640 and argmax
FP16 N=2048 captures. No paper answers, previous reports, or operator-specific
diagnoses were supplied. A third matmul run tests compact evidence presentation.
No new profiling, compilation, benchmark generation, commits, or pushes.

## Initial Results

| Trial | Quantitative checks | Explanation quality |
|---|---|---|
| Matmul, standard evidence | 33/33 exact records; ratios/SASS/action coverage pass | Correct comparison including Torch, but mostly activity restatement and unresolved alternatives. |
| Argmax, standard evidence | 60/60 exact records; ratios/SASS/action coverage pass | Useful one-chunk vs two-chunk implementation/config mechanism supported by instruction/shared-work counts and equal input sectors. |
| Matmul, compact evidence | 33/33 exact records; ratios/SASS/action coverage pass | More concrete per-iteration synchronization/overlap hypothesis, but still incomplete evidence use. |

All 126 submitted raw metric records match exactly. All nine actions are covered;
CSV arithmetic and SASS counts pass. This is extraction accuracy, not a reliable
causal-analysis success rate.

Argmax is close to the requested paper style: it names the selected tile-width
difference, connects it to reduced repeated reduction/control work, and checks
traffic, stalls and resources instead of claiming an intrinsic compiler advantage.
It correctly computes the FP16 input as 8 MiB. It does not isolate the precise
latency contribution, which is an appropriate limit rather than a reason to omit
the mechanism. Lower long-scoreboard ratios are not claimed as the advantage.

Matmul does not yet meet the explanatory bar. It identifies configuration/staging
differences and rejects simplistic resource-total reasoning, but concludes mostly
with low active-warp/tensor activity. Worse, it incorrectly says theoretical
occupancy/resource-limit counters are absent; they are present in the supplied
numeric export/raw reports. It imports SASS but discusses only listing totals,
not instruction-family differences. Removing compiler-pass requirements alone did
not solve selective evidence use.

The exact-value auditor does not certify narrative claims. Both agents kept CSV
and NCU ratios distinct, included the fastest available CSV reference, and did
not establish a compiler defect. The complete selected winner configurations
remain confounders when attributing effects to a backend compiler alone.

## Harness Follow-Up

The initial views are bulky: each numeric record repeats identity fields, and
SASS parser output includes all instruction rows before the opcode histogram.
[evidence_index.py](evidence_index.py) creates an unranked compact view of all
numeric metrics grouped by prefix, plus all static opcode counts and warnings.
No metric or opcode family is selected as relevant. It preserves action identity,
exact values and units; all 867 matmul records reconstruct exactly. Four index
tests pass; the existing CSV/SASS helper test suites have 13 passing tests.

The extra fresh matmul trial uses the same v6 skill/task and raw reports, with
the compact view and preimported SASS added. This changes presentation and
preimport availability together, so it is not an isolated indexing ablation.
The compact-view report makes a more concrete, appropriately qualified inference:
TileLang's explicit per-iteration synchronization and two configured stages can
constrain overlap, consistent with its lower measured activity. It does not
directly prove the stall or isolate configuration from compiler scheduling.
It still says theoretical occupancy counters are absent without discussing
available `launch__occupancy_limit_*` resource limits, and only reports SASS totals
despite the supplied opcode histograms. Thus compact presentation alone did not
reliably resolve the evidence-use weakness. Neither an indexing benefit nor its
absence is established by this singleton comparison.

**Recommendation:** use v6 as the next paper-style candidate, not a validated
autonomous analyst. Keep numeric/helper checks and a prose review. No compiler
inspection was needed for any of these three reports. A future test should ask
the agent to tie claimed missing evidence to an actual inventory check and evaluate
on held-out operators, rather than adding operator-specific diagnosis hints or
forcing a complete compiler-source/PTX chain. This turn stops after the three
forward tests; the frozen skill is not silently revised after seeing results.

## Scope

These are singleton exploratory tests on previously used cases, not independent
held-out operators or statistical evidence that a policy is best. Models receive
no inherited conversation, but shared-storage isolation is instruction-based,
not filesystem-enforced. Eight minutes is a soft target, not a hard timeout.
The compact helper addresses discovery, not the missing matmul stall-attribution
data or absent captured IR. Neither model-only nor harness-only blame is justified.

Source package pins match the PDF-era stack, but report import uses a CUDA 13.2
NCU path. Capture-time framework versions/native binary lineage are not fully
recorded. This caveat is distinct from proven version drift; no new kernel code
was compiled in these tests. Shell startup's Lmod warning did not prevent extraction.
