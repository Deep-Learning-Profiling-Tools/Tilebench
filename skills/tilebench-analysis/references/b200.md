# B200 Scope

Identify the actual capture device and software stack from evidence.
TileBench's hardware helper maps NVIDIA capability `(10, 0)` to `blackwell`.

- Blackwell paths may use tensor memory and `tcgen05` instructions. Verify emitted
  code; an implementation can still select an older instruction path.
- Register/shared-memory allocation and selected CTA size can limit residency.
  Use the report's device attributes and limiting-resource counters, not a fixed
  SM count or a warp ceiling copied from a different capture.
- TMA, lane-issued copies, and synchronous load/store paths are distinct. Verify
  the selected path before attributing a lack of overlap to the DSL or compiler.
- Available counter names depend on architecture and NCU collection. Inventory
  the report; no universal throughput threshold identifies a bottleneck.
- Some saved TileBench TileLang captures use reduced core metrics and kernel
  replay after application-replay stalls. Inspect capture notes instead of assuming
  every report is full or cache-equivalent. The replay failure does not alone prove
  a kernel synchronization bug or a profiler defect.

Benchmark maxima, winning tiles, compiler versions, and replay methodology belong
to the experiment. Do not assume this machine's current setup reproduces them.
