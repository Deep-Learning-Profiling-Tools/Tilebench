# GH200 Scope

This is an untested adaptation of the NVIDIA saved-report workflow. GH200 captures
use the same report API and TileBench artifact naming, but not B200 architecture
assumptions. TileBench maps capability `(9, 0)` to `hopper`.

- Hopper supports TMA; TileBench's `supports_tmem()` is false on this architecture.
  Do not apply Blackwell TMEM/tcgen05 explanations without appropriate code evidence.
- The same implementation file can branch on detected hardware and produce a
  different kernel. Inspect the capture-time branch, config and generated code.
- Use GH200's captured device attributes, resource limits and metric inventory.
  Never substitute B200 winners, occupancy ceilings or peak normalizations.
- Discover backend/dtype coverage from artifacts, not an assumed two-DSL roster.
  Benchmark availability and saved-profile availability are separate questions.

Single-kernel analysis remains the default. A cross-hardware comparison requires an
explicit request and matching workload/provenance; different timings alone do not
identify which architectural or code difference caused the gap.
