# Protocol revision 3 (study-owner decision, 2026-10-06)

Revision 3 replaces revision 2 (ten rounds, up to three generations per round,
every eligible dtype). It changes the task unit, the round protocol, the
compliance checker, and adds USD cost accounting, provider telemetry and an
adaptive scheduler. Base and Enhanced use it identically; the only difference
between them remains the Optimization Skill.

## 1. The revision-2 pilot is excluded

`formal_b200_base_2026-10-06` (S_llm `81001678`, 51/440 trajectories, 563
closed rounds, 16 review_required) is a protocol/infrastructure engineering
pilot. Its artifacts are kept unchanged (`SUPERSEDED.json` beside them);
`tilebench/llm/v2/manifests/excluded_campaigns.yaml` lists it, and code
enforces the exclusion:

| Use | Enforced by |
|---|---|
| distillation source | `distillation.access.EvidenceScope.allows` refuses the campaign by name and every state that is not schema `/3` (protocol revision 3) |
| formal E(B) | `devtools.recompute_metrics` skips excluded campaigns and non-revision-3 states (`_not_scored`) |
| resume / extension | `campaign.prepare_track` refuses the campaign name; `_check_resume` refuses any state whose protocol identity differs |
| review / re-evaluation | `review-resolve` and `re-evaluate` refuse to write into an excluded campaign |

Allowed uses: checker-v2 offline regression, infrastructure/debug evidence.

## 3. Trajectory: 5 rounds, exactly one generation per round

`study.yaml` revision 3: `rounds: 5`, `max_generations_per_round: 1`. One
round = generate one candidate -> parse -> compliance check -> (when allowed)
verification, evaluation, timing -> close. Format / interface / compile /
runtime / numerical / timing failures and confirmed contract violations close
the round; the next round's prompt carries the trajectory's own previous code
(or, after a violation or an unparsable response, the last compliant code)
and the sanitized diagnostics. A valid but slower candidate is recorded and
never replaces the best. No performance early stop: every trajectory runs 5
rounds. Every sent generation is charged whatever its outcome. Transport
retries are not candidate attempts: up to 3 retries for transport failures
and, separately, up to 12 for HTTP 429 (each after the provider's
Retry-After / reset); a 429 that reports exhausted quota stops the trajectory
as a provider refusal. The compliance-repair template is removed.

## 4. Checker v2

Verdicts: `clear`, `audit_only` (recorded, evaluated normally, never blocks,
never sent to the model), `review_required` (blocks; high-risk ambiguity
only), `confirmed_violation` (closes the round).

| Evidence | Verdict |
|---|---|
| autotuner / hidden search entry points; reference-library delegation (also through `F = torch.nn.functional`, `getattr(torch, "x")`, host `a @ b`); evaluator / process-control imports; precision-state changes | confirmed_violation |
| contract rule of level `confirmed` on a computational line | confirmed_violation |
| persistent state (module-level object, `global`, mutable default argument, functools cache) written with tensor data or a tensor address / identity, per a data-flow analysis of the host code | review_required |
| tensor-identity dictionaries; `eval`/`exec`/`open`/`setattr`/...; `importlib`/`inspect`/`shutil`; stream / CUDA-graph primitives; RNG re-seeding; a configuration loop with timing calls; `torch.ops.*`; dynamic attribute lookup on torch; monkey-patching an imported module | review_required |
| contract rule of level `suspicious` with positive, computational, identifier-level evidence | review_required |
| any `required_evidence` miss | audit_only |
| suspicious-rule hit that is a pure operator token (`<=`), on a degenerate-input early exit (`if n <= 1: return`), on a non-computational line, or a cache construct (decided by the data-flow analysis) | audit_only |
| local / metadata use of `data_ptr`; persistent state holding only non-tensor values (compiled-kernel caches); `torch.cuda.synchronize`/timing calls; `os`/`sys`/`pathlib`; `getattr` | audit_only |

Offline regression on the pilot (548 archived candidates, no API, no GPU,
nothing written into the pilot): the 16 review_required candidates -> 16
audit_only; 527 clear -> clear; 5 clear -> audit_only (local data_ptr reads);
0 new review_required, 0 new confirmed_violation. Synthetic negatives
(`tests/llm_v2/test_protocol_v3.py`): hidden autotune, persistent output
cache, torch delegation, evaluator import, precision tampering stay
confirmed / review_required; output aliasing and cross-call output caching
remain execution-confirmed by the worker.

## 5. Metrics

`C_i = sum_(j<=i) c_j`, i in 1..5, one generation per round, failed
generations included. Two independent budget axes with the same definition:
E_token(B_token) (logical tokens; the main metric) and E_usd(B_usd)
(estimated list-price USD). `E_bar(B)` is the mean over the 45 predeclared
operators (no inner dtype average); missing / incomplete / unknown-cost tasks
keep the conservative handling (exact mean undetermined, lower bound counts
them as 0, unknown is never 0).

## 6. USD cost

`manifests/api_pricing.yaml` (version 2026-10-06.1, official pages fetched on
2026-10-06): gpt-6.1-sol standard short context (<= 272K input) input $2.00,
cached $0.10, cache write $2.50, output $10.00 per 1M tokens (long context
$4.00 / $0.20 / $5.00 / $15.00); claude-opus-5-5 standard, global routing:
input $4, 5-minute cache write $5, 1-hour cache write $8, cache read $0.20,
output $20. OpenAI ordinary input = input - cached - cache_write; reasoning
tokens are inside output_tokens. Anthropic input_tokens are the uncached
tokens; cache writes split 5m / 1h; thinking is inside output_tokens. A
response reporting another tier / geography gets no rule (`unknown`), never a
guessed price. Every transport row, attempt, ledger row and trajectory
(`cost_summary`) carries `pricing_snapshot_sha256`, `pricing_rule_id`,
`estimated_cost_usd`, `estimated_cost_lower_bound_usd`, `usd_cost_status`
(`exact_from_usage_and_frozen_price` | `partial_lower_bound` | `unknown` |
`not_sent`). Campaigns pin the snapshot; a formal resume refuses a change.
`cost-report` aggregates by provider / model / DSL / operator. Optional
`billing-reconcile` stores the providers' aggregated billed cost under
`billing_reconciliation/` only when admin credentials exist; it never fills
the estimated fields.

## 8. Telemetry and concurrency

Adapters archive whitelisted rate-limit / request-id response headers
(never auth, cookie, organization or project headers), the last stream event,
the provider error body and status. `schedule` runs all DSL tracks of ONE
model in one process: generation concurrency starts at 3, doubles (3 -> 6 ->
12 -> 24 -> ...) only after real rate-limit headers show >= 50 % headroom,
halves on a 429 (pausing until Retry-After / reset) or on sustained overload,
and stops issuing requests while 16 candidates per process (32 for the two
processes) wait for evaluation. GPU evaluation stays serialized by the device
lock. Telemetry (concurrency, requests/min, tokens/min, 429 / overload /
unknown-charge rates, RSS / CPU, pending evaluations, ramp / backoff events)
is written under `<campaign>/telemetry/` and never reaches a prompt or a
score. Scheduling never changes model settings, prompts, rounds, checker or
scoring.

Graceful pause: `touch <campaign>/STOP` (or `STOP_<model>`). No new request
starts (nothing is sent or logged as `sending`), in-flight requests finish
and are archived, running evaluations finish, every trajectory pauses at a
resumable boundary and the scheduler exits. Remove the file and run the same
`schedule ... --resume` command to continue.

## 9. Enhanced and distillation

Enhanced uses the same selected dtype, the same largest case, 5 rounds, one
generation per round, checker v2 and model settings; only the Optimization
Skill is added. For each DSL on B200 the distillation input of one fold skill
is the base trajectories of the ~30 training-fold operators x 2 models x 5
rounds (about 300 source rounds), from revision-3 formal campaigns only. Each
of Triton, cuTile and TileLang gets its own three fold skills; DSLs are never
mixed.
